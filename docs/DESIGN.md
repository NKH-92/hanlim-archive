# DESIGN.md — 한림 문서고 관리 시스템

모든 UI 값의 단일 출처. 컴포넌트에 새 값이 필요하면 여기에 토큰을 먼저 추가한 뒤 사용한다.
원시 hex, 임의 spacing 숫자를 컴포넌트에 직접 쓰지 않는다.

## 1. Atmosphere / Signature

제약 GMP 문서고의 **규제산업 운영 콘솔**. 차분한 쿨 슬레이트 바탕 위에 딥 워킹 블루를 브랜드 면으로 쓰고,
제한적인 액션 옐로를 비파괴적 최우선 행동과 선택 위치에만 쓴다.
정보가 장식보다 앞선다: 그림자 대신 헤어라인 보더, 카드 대신 행(row), 큰 여백 대신 정렬된 밀도.
위치 코드와 문서번호는 모노스페이스로 각인해 "찾아갈 좌표"라는 정체성을 준다.
밀도와 정렬이 신뢰를 만든다. 문서 식별의 정확성, 위치 확인에 필요한 이동, 작업 실수 예방과 입력 보존을 품질 기준으로 삼는다.

Do / Don't
- Do: 헤어라인(`--line`)으로 구획하고, 표 형태로 정렬한다. 숫자는 tabular-nums.
- Do: 위치·문서번호는 `--font-mono`. 내부 보관코드는 브라우저 업무 화면에 노출하지 않는다.
- Don't: 카드마다 그림자를 주지 않는다(보더 우선, 그림자는 떠 있는 레이어 전용).
- Don't: 섹션마다 eyebrow 라벨을 달지 않는다. 제목 하나로 충분하다.
- Don't: 제품 가치만 말하는 마케팅형 히어로. 검색 홈의 운영 히어로 안에서도 검색 입력이 첫 포커스 작업이다.

- 대비 사전 검증(실측): `--gray-900`/`--surface` ≈ 16.2:1, `--gray-500`/`--surface` ≈ 5.5:1,
  가장 밝은 배경인 `--gray-500`/`--bg` ≈ 5.1:1로 본문 AA(4.5:1) 충족,
  `#ffffff`/`--primary` ≈ 6.7:1, 상태색/상태soft 모두 ≥ 4.5:1.
- 색 잠금: 브랜드·링크·활성 상태는 `--primary`, 비파괴적 최우선 행동과 선택 위치는 `--action`만 쓴다.
  초록·주황·빨강은 상태 의미 전용이며 장식에 쓰지 않는다. action 면에는 `--action-ink`만 사용한다.

## 3. Typography

- 본문 스택: `system-ui, -apple-system, "Segoe UI", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`
  (한국어 전문 표준 서체. Inter 기본값 대체가 아니라 한글 가독성을 위한 의도적 선택)
- 코드 스택 `--font-mono`: `ui-monospace, "Cascadia Code", "SF Mono", Consolas, monospace`
  (위치 코드, 문서번호, 보관코드 전용)
- 숫자: 카운트·통계·표의 숫자는 `font-variant-numeric: tabular-nums`.

| 역할 | 크기/두께/행간/자간 |
|---|---|
| 페이지 제목 h1 | 22px · 700 · 1.3 · 0 |
| 섹션 제목 h2 | 16px · 700 · 1.35 · 0 |
| 소제목 h3 | 13.5px · 700 · 1.4 |
| 본문 | 14px · 400 · 1.55 |
| 메타/캡션 | 12.5px · 500 · 1.45 |
| 라벨/테이블 헤더 | 12px · 600 · 1.4 (`--gray-600`) |
| 위치/코드(모노) | 13px · 600 · 1.4 |
| 통계 숫자 | 22px · 700 · 1.2 · tabular-nums |
| 위치 디스플레이 lg | 22px · 700 · 1.25 · 0 · mono · tabular-nums |

본문과 컴포넌트의 자간은 `0`으로 고정하고 뷰포트 너비에 따라 글자 크기를 바꾸지 않는다.

## 4. Spacing

기본 단위 4px. 모든 margin/padding/gap은 이 배수만 쓴다.

`--sp-1: 4px` · `--sp-2: 8px` · `--sp-3: 12px` · `--sp-4: 16px` · `--sp-5: 20px` · `--sp-6: 24px` · `--sp-8: 32px`

- 패널 내부: `--sp-5`. 행(row) 내부: `--sp-3 --sp-4`. 섹션 간: `--sp-4`.
- 페이지 컨테이너: 최대 1440px, 거터 `--sp-6`.
- 사이드바 폭: 240px(≥1100px 고정).

## 5. Components

- 반경: `--r-lg: 10px`(패널·모달) · `--r-md: 8px`(버튼·입력) · `--r-sm: 6px`(배지·미니 요소) · pill은 999px(칩·상태 배지). 이 4단 외 값 금지(shape lock).
- **버튼**: 높이 40px(기본)/32px(sm). primary = `--primary` 배경 + `#ffffff` 텍스트, hover `--primary-strong`.
  secondary = `--surface` 배경 + `--line` 보더 + `--gray-700` 텍스트, hover `--gray-50`.
  action = `--action` 배경 + `--action-ink` 텍스트, hover `--action-strong`. 한 화면에 하나만 허용하며 폐기·삭제·계정 중지에는 금지한다.
  danger = `--danger-soft` 배경 + `--danger` 텍스트. focus-visible: 2px `--primary` 아웃라인(offset 2px).
- **아이콘 버튼**: 기본 `36×36px`, 아이콘 `--gray-600`. 1099px 이하의 내비게이션 버튼과 760px 이하의 모든 아이콘 버튼은 `44×44px` 이상으로 둔다. 텍스트 대신 익숙한 아이콘과 접근 가능한 이름을 사용한다.
- **입력/셀렉트**: `--surface` 배경 + 1px `--line` 보더 + `--r-md`, 높이 40px. hover 보더 `--gray-300`,
  focus 보더 `--primary` + 3px `--ring` 링. placeholder와 검색 아이콘은 본문 AA를 충족하는 `--gray-500`.
- **모바일 터치·입력**: 760px 이하에서는 입력·셀렉트·텍스트영역 글꼴을 16px, 주요 버튼·아이콘 버튼과
  입력 높이를 44px 이상으로 둔다. iOS Safari 포커스 확대와 작은 터치 목표를 만들지 않는다.
- **테이블/리스트 행**: 헤더 `--gray-50` 배경 + 12px/600 `--gray-600`, 행 높이 ≥44px,
  행 구분 1px `--line`, hover `--gray-50`. 위치 셀은 `--font-mono` + `--primary` 텍스트.
- **상태 배지**: pill, 12px/700, soft 배경 + 상태색 텍스트. 색 이름을 클래스 계약으로 사용하지 않고 `document-*`, `account-*`, `ledger-*`, `campaign-*`, `import-*`, `snapshot-*`, `review-*`, `change-*`처럼 업무 의미를 클래스에 기록한다. 문서 보관중·완료·생성은 success, 진행·대기·검토는 warning, 폐기·취소·사용중지·반려는 중립 회색, 보안 검토·실패는 danger, 대장 포함·권한 요건은 primary를 사용한다.
- **칩(필터)**: pill, 12.5px/600, `--surface`+`--line` 보더, 활성 = `--primary-soft`+`--primary`.
- **탭**: 언더라인 형. 비활성 `--gray-500`, 활성 `--gray-900` + 2px `--primary` 밑줄.
- **패널**: `--surface` + 1px `--line` + `--r-lg`. 그림자 없음.
- **사이드바**: `--primary-deep`, 우측 1px 반투명 구분선. 항목 13.5px/600 흰색 보조 잉크, 활성은 반투명 흰 배경 + 좌측 `--action` 레일.
- **사이드바 정보구조**: 일반 navigation은 검색을 중심으로 `문서 검색·보관 위치`를 접지 않은 1차 메뉴로 항상 제공한다. 권한별 `업무·운영` 그룹은 현재 화면이 속한 그룹을 자동으로 열고 사용자가 연 상태를 브라우저에 기억한다. `can_manage_documents`에는 전역 `문서 등록`과 공식 원본 생성 경로인 `엑셀 대장 동기화`, `can_manage_disposals`에는 `문서 폐기·폐기 문서`를 추가한다. 세트·legacy CSV 가져오기·검색 리포트·데이터 품질은 일반 navigation에 두지 않고 `/admin`의 권한별 `고급` 영역에서 제공한다.
- **모바일 하단 탭**: `검색·위치·더보기`를 제공하고, 권한별 문서 등록·엑셀 동기화·폐기·운영 항목은 `더보기` 드로어 안에 둔다. 일반 navigation에서 제외한 관리자 고급 도구는 모바일 탭과 명령 팔레트에도 중복 노출하지 않는다.
- **엑셀 대장 동기화와 문서 등록**: `엑셀 대장 동기화`는 엑셀 전체 동기화만 제공하고, 수시 건별 등록은 전역 `+ 문서 등록` 동작으로 처리한다. 문서 수정·개정·위치 이동·폐기는 `/app` 문서 작업 공간에서 시작한다.
- **승인 사용자 추가**: 사용자 관리의 시스템관리자 전용 동작으로 제공한다. 이메일·이름·부서·임시 비밀번호를 한 계정씩 입력하고, 조회 전용 User·최초 비밀번호 변경 강제 결과를 확인한 뒤 생성한다. 권한 설정은 생성 후 별도 사용자 권한 화면에서 수행하며 비밀번호는 오류 화면에 재표시하지 않는다.
- **대분류 관리**: 제목 행에서 문서 등록·검색·폐기 조건에 쓰이는 기준정보임을 설명하고, 필요한 기능을 찾기·추가·이름과 설명 수정·사용중지와 다시 사용으로 한정한다. 정렬 순서 숫자는 업무 화면에 노출하지 않고 관리 목록은 사용 중 항목을 먼저 이름순으로 표시한다. 항목이 많아져도 이름·설명 검색과 `사용중지 항목 포함`으로 좁혀 보며, 각 항목의 수정 폼은 기본 접힘으로 둔다. 사용중지는 기존 문서의 분류를 지우지 않는다는 결과를 동작 옆에 설명한다.
- **30,000건 검색·용량 상태**: 텍스트 검색은 최대 30행과 `더보기`를 사용하고 정확한 총페이지를 만들지 않는다. `더보기`는 기존 행을 다시 그리지 않고 새 행만 이어 붙인다.
  전체/필터 목록도 `pageSize + 1`만 읽어 다음 페이지 여부를 표시하고, 상태 단일 목록만 용량 카운터의 정확한 건수를 쓴다.
  운영 관리에는 현재/30,000건 용량과 Core projection의
  `ready/pending`·색인 건수·dirty 잔량을 한 줄 패널로 표시하며 내부 보관코드는 노출하지 않는다. 별도 Search D1,
  outbox, shadow generation 상태는 사용자 화면에 존재하지 않는다.
- **엑셀 대장 동기화**: 동기화 사유 입력 → 파일 선택 → 구조 확인 → 전송 진행률 → 유형별 요약·before/after·제외 목록 검토 → 저장된 사유 재확인·승인 참조 입력 → 명시적 반영 순서를 유지한다. 사유는 작업 생성 감사에 저장하며, 파일 선택만으로 현재 대장을 바꾸지 않는다. 제외·폐기 해제와 개정 이력 충돌은 위험 경고로 구분한다. 모바일 단계 표시는 5개 전체 진행 위치와 현재 단계의 이름·설명을 한 화면 안에 함께 보여주며 가로 스크롤을 만들지 않는다. 문서데이터와 인쇄용 관리대장은 `문서종류` 다음, `랙 위치 (번호)` 앞에 `랙 위치 (구역)`을 표시한다.
- **검색 하이라이트(mark)**: `--primary-soft` 배경 + `--primary` 텍스트, radius 2px, 추가 padding 없음. 장식 금지, 검색어 일치 표시 전용.
- **문서 결과**: 아래 검색과 입력 경험 계약을 따른다. 네이티브 표와 명시적 빠른 보기를 사용하며 모바일에서도 위치를 표시한다.
- **보관 위치**: 문서 작업 공간과 분리된 전용 화면에서 전체 도면을 제공하고, 랙 선택 시 상세 패널과 해당 위치 문서 링크를 연다. 모바일은 44px 이상의 랙 목록을 도면보다 먼저 제공하고 도면의 작은 랙 표시는 탐색 대상으로 사용하지 않는다. 문서 상세의 위치 도면과 랙 열·선반 표시는 접지 않고 기본 노출하되, 모바일 미니 랙은 가로 스크롤 없이 모든 열이 맞게 축소된다. 모든 랙과 면은 사용자가 해당 면을 바라본 기준으로 왼쪽부터 1열, 아래부터 1선반으로 표시하며 면 방향에 따른 열 반전을 사용하지 않는다.
- **준비 문서 세트**: 목록은 이름·설명 검색, `전체/편집 가능/잠김/폐기 포함/제외 포함` 필터와 최근 수정순 정렬을 제공한다. 검색 결과는 최대 200건을 한 번에 선택해 기존 원자적 추가 경로로 전달한다. 복제한 세트는 원본 구성원을 그대로 가지되 항상 편집 가능한 상태로 시작한다.
- **폐기 관리**: 일반 문서 검색·목록에는 폐기 문서를 표시하지 않는다. `/documents/disposal` 안에서 `폐기 대상/정기폐기 작업/폐기 문서`를 전환하고 현재 폐기 상태의 문서만 별도 탭에 표시한다. 모바일의 폐기 대상 필터는 기본 접힘으로 결과를 먼저 보여주고, 적용된 조건은 필터 밖의 해제 가능한 칩으로 유지한다. 폐기 확인 모달은 320px 화면에서도 가로 넘침 없이 대상과 버튼을 보여준다. 내부 `frozen` 상태는 화면에서 `대상 확정`으로만 표시하며 저장값과 감사 사건명은 바꾸지 않는다.
- **문서 등록·수정**: 태그는 검색 가능한 다중 선택으로 향상하되 체크박스를 기본 계약으로 남긴다. 모바일은 입력 전 미리보기 요약을 접은 상태로 시작하고 데스크톱은 펼쳐 보여준다. 고정 저장 바는 필수 입력 완료도를 표시하고, 입력 변경 뒤 이탈할 때 브라우저 경고를 사용한다. 선택 위치에는 해당 면·열·단의 활성 문서 수와 같은 위치 문서 링크를 표시한다.
- **도움말·문의**: 검색 팁과 담당자 연락처에 앞서 현재 사용자 권한으로 실행할 수 있는 주요 작업 바로가기를 제공한다. 권한이 없는 관리 작업 링크는 노출하지 않는다.
- **업무 헤더**: 검색 홈과 결과를 포함한 모든 작업 화면은 공통 헤더를 사용하며 검색 입력 위치가 변하지 않는다.
- 비활성(disabled): opacity .45 + pointer-events 차단.

## 6. Motion

- 지속시간 120–180ms, `ease-out`. 배경/보더 색 전환과 opacity/transform만 사용(GPU 합성).
- 레이아웃 속성(width/height/top) 애니메이션 금지.
- 토스트: translateY+opacity 200ms. 드로어(모바일 내비): transform 220ms.
- `prefers-reduced-motion: reduce` 시 모든 transition/animation 1ms로 축소.

## 7. Depth

전략은 **보더 우선** 하나로 통일. 표면은 전부 1px `--line`으로 구획하고 그림자를 겹치지 않는다.

| 레벨 | 용도 | 값 |
|---|---|---|
| 0 | 패널, 행, 카드 | 보더만 (`1px solid --line`) |
| 1 | 떠 있는 바(벌크 액션, 스티키), 팝오버 | `--shadow-1: 0 4px 16px rgba(24, 33, 47, .08)` |
| 2 | 모달, 커맨드 팔레트, 토스트 | `--shadow-2: 0 12px 40px rgba(24, 33, 47, .18)` |

스크림: `rgba(24, 33, 47, .5)`. 포커스 링: `--ring: rgba(30, 85, 196, .22)`.

알파 예외(토큰 파생값): 딥/다크 면 위 반투명 화이트 `rgba(255,255,255,.12~.92)`(로그인 사이드, 벌크 바, 도면 라벨),
도면 오버레이의 primary 알파 틴트 `rgba(30,85,196,.05/.45)`. 이 외의 알파 색 신설 금지.

## 8. 검색과 입력 경험 계약

### UI 개선 적용안

- 검색 화면을 열 때는 비교 보기를 항상 끈 상태로 시작한다. 이전 브라우저 설정을 복원하지 않는다. PC에서는 필요할 때 문서번호·개정을 독립 열로 보여주는 비교 보기를 켤 수 있다. 모바일은 문서명 아래 식별정보를 유지한다.
- 빠른 보기의 현재 행은 파란 배경과 왼쪽 선으로 표시하며 체크박스 선택과 구별한다. 랙은 상단 열·왼쪽 선반 축과 선택 위치를 표시한다.
- 개정 교체는 이전본 폐기를 명시하는 danger 버튼, 엑셀 최종 반영은 검토 건수·제외 영향을 설명하는 primary 버튼을 사용한다.
- 서버 입력 오류는 요약과 각 입력 아래 메시지를 함께 표시하며 aria-describedby로 연결한다. 입력값은 보존한다.
- 상세·개정·동기화 상세 화면은 상위 메뉴의 현재 위치를 표시한다.
- 추가 토큰: `--preview-inline-min: 1040px`, `--text-identity: 14px`, `--rack-axis-width: 24px`.


기존 모든 색상값을 유지한다. PC 관리와 모바일 검색·위치 확인을 우선한다.

- 공통 크기 토큰: `--text-title: 22px`, `--text-section: 16px`, `--text-body: 14px`, `--text-meta: 12.5px`, `--control-height: 40px`, `--touch-height: 44px`, `--preview-width: 320px`.
- 검색 홈과 결과는 같은 헤더와 검색창을 사용한다. 결과는 네이티브 table이며 행 전체 클릭·행 Tab 정지를 사용하지 않는다. 문서명은 상세, 버튼은 빠른 보기, 체크박스는 일괄 선택이다.
- PC 기본 열은 선택(권한자), 문서명·번호·개정, 위치, 분류, 빠른 보기다. 보관중은 목록 제목에 표시한다. 제·개정일은 선택 열이다.
- 모바일에도 문서명·번호·개정·위치를 모두 표시한다. 숫자·좌표는 임의 생략하지 않고 단어 단위로 줄바꿈한다.
- 빠른 보기는 작업 영역 1040px 이상에서 320px 옆 패널, 그 아래는 modal, 760px 이하는 전체 화면 dialog다. 랙 안내는 왼쪽 1열·아래 1선반을 유지한다.
- 새 조건 검색은 미리보기·선택을 초기화하며 더보기는 같은 결과의 선택을 유지한다. 복귀는 최신 결과를 조회하며 체크 상태를 복원하지 않는다. 탭 상태는 사용자·세션 범위에서 30분만 유효하고 문서 내용은 저장하지 않는다.
- 보관중 상세는 위치와 관리 동작을 상단에 둔다. 폐기·제외 상세는 상태를 우선하고 마지막 기록 위치를 접어 제공한다.
- 연속 등록은 분류·위치 유지 옵션을 기본 해제한다. 번호·개정·이름·날짜·태그·비고는 다음 문서에 재사용하지 않는다.
- 입력폼은 저장 중 상태와 오류 요약을 공통 제공한다. 네트워크 결과가 불명확하면 입력을 보존하고 저장 여부 확인 전 재전송을 막는다. 서버 성공 후에만 완료 화면으로 이동한다.

## 8. 공개 랜딩과 로그인

랜딩은 업무 화면에 진입하기 전에 검색 → 위치 → 이력의 가치를 설명한다. TDS Mobile의 색상·타이포그래피 토큰, 주요/보조 버튼, 목록의 정보 위계, 지속되는 입력 라벨 원칙을 참고한다. 한림의 기존 브랜드 색상과 서버 렌더링 구조를 유지하며, 아래 값은 `.landing-page` 안에서만 사용한다.

| 토큰 | 값 | 역할 |
|---|---|---|
| `--landing-width` | `1200px` | 콘텐츠 최대 폭 |
| `--landing-gutter` | `32px`, 모바일 `20px` | 화면 좌우 여백 |
| `--landing-section-space` | `112px`, 태블릿 `80px`, 모바일 `64px` | 섹션 상하 여백 |
| `--landing-gap` | `64px`, 태블릿 `48px`, 모바일 `32px` | 소개와 예시 사이 여백 |
| `--landing-display` | `3.5rem`, 태블릿 `3rem`, 모바일 `2.25rem` | 첫 제목 |
| `--landing-title` | `2.5rem`, 모바일 `1.875rem` | 섹션 제목 |
| `--landing-body` | `1.0625rem` | 소개 본문 |
| `--landing-small` | `.875rem` | 예시 문서·보조 설명 |
| `--landing-caption` | `.75rem` | 예시 번호·메타 |
| `--landing-radius` | `24px` | 제품 예시와 로그인 패널 |
| `--landing-control-radius` | `12px` | 랜딩 입력·버튼 |
| `--landing-header-height` | `80px`, 모바일 `64px` | 고정 내비게이션 높이 |
| `--landing-control-height` | `52px` | 주요 버튼·입력 |
| `--landing-motion` | `160ms ease` | hover·press 상태 전환 |

- 공개 소개에만 큰 제목·넉넉한 여백·위 두 반경을 허용한다. 글자는 rem과 고정 breakpoint로 조정하고 임의 vw 크기를 사용하지 않는다. 업무 화면의 밀도와 반경은 기존 계약을 따른다.
- 기본 제목은 두 줄, 설명은 짧은 두 문장으로 구성한다. 본문은 `--gray-500` 이상 대비로 표시하고 `--gray-400`은 장식에만 쓴다.
- 주요 로그인은 primary 채움, 살펴보기·헤더 로그인은 연한 배경으로 구분한다. 모든 링크·버튼의 터치 높이는 44px 이상, 입력 글꼴은 16px 이상이다.
- 예시는 정적인 설명임을 보이는 글자와 접근 가능한 이름으로 명시한다. 문서명 → 번호·개정 → 위치의 위계를 유지하며 작은 화면에서도 좌표를 생략하지 않는다.
- 랙은 위에서 6→1선반, 왼쪽에서 1→7열이다. 4열·3선반 강조는 위에서 네 번째 행에 놓고 색과 텍스트를 함께 사용한다.
- 좁은 화면의 선택 셀은 점으로 표시해 격자 높이를 유지한다. 정확한 열·선반은 도면 위 텍스트와 접근 가능한 설명에 남긴다.
- 로그인에는 항상 보이는 라벨과 native autocomplete를 유지한다. 계정 문의 상세만 접을 수 있으며 로그인 오류·설정 안내는 폼 바로 위에 항상 표시한다.
- 움직임은 상태 전환에만 사용한다. `prefers-reduced-motion`에서는 전환을 제거하고 자동 재생·스크롤 기반 콘텐츠 숨김은 사용하지 않는다.
